# Предложение дополнительных проверок восстановления

Не применено. Действующий systemd timer остаётся ежедневным в 07:30 UTC.
Автоматическая проверка разрешений отклонила persistent расширение расписания;
перед изменением production timer требуется отдельное согласие пользователя.

Предлагаемый дополнительный OnCalendar:
`*-*-* 08..23:00,15,30,45:00 UTC` — проверки каждые 15 минут с 08:00 до 23:45 UTC.
Основной запуск 07:30 UTC сохраняется. Можно также включить Persistent=true,
чтобы после простоя сервера восстановить пропущенный запуск.

Завершённый workflow возвращается до создания OpenAI runtimes и Telegram Bot.
При незавершённом background ranking восстанавливаются те же ranking ID,
request key, кандидаты, cutoff и response ID. Первый новый ranking POST
при восстановлении запрещён: для него требуется существующий checkpoint.
При обрыве GET повторяется чтение, а не генерация. Если primary ranking уже
завершился, но обычная проверка/исправление его результата ещё не начиналась,
она может потребовать следующего платного запроса. Text/image/review следуют
обычному workflow; неизвестный исход Telegram-доставки не переигрывается.

Даже с такими ограничениями дополнительное расписание расширяет возможности
платных вызовов и доставки в течение дня. Это причина отдельного согласования.
