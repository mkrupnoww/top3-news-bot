# Две проверки восстановления ежедневного выпуска

2026-10-13 пользователь разрешил ровно две дополнительные проверки с интервалом
15 минут. Расписание ограничено утренним окном:

- 07:30 UTC — основной production workflow;
- 07:45 UTC — первая проверка восстановления;
- 08:00 UTC — вторая и последняя проверка восстановления.

Позднее в этот день таймер больше не срабатывает. Если выпуск не доставлен,
причина проверяется вручную. Это фиксированные календарные точки, а не 15 минут
после завершения предыдущей попытки. Если oneshot ещё выполняется, systemd
не запускает его вторую копию; дополнительная точка не переносится на потом.
Persistent=false сохраняется: дополнительных catch-up запусков после простоя нет.

Завершённый workflow возвращается до создания OpenAI runtimes и Telegram Bot.
При незавершённом background ranking восстанавливаются те же ranking ID,
request key, кандидаты, cutoff и response ID. Первый новый ranking POST
при восстановлении запрещён: для него требуется существующий checkpoint.
При обрыве GET повторяется чтение, а не генерация. Если primary ranking уже
завершился, но обычная проверка/исправление его результата ещё не начиналась,
она может потребовать следующего платного запроса. Text/image/review следуют
обычному workflow; неизвестный исход Telegram-доставки не переигрывается.

Установка на cloud-001 выполняется обычным scripts/deploy_server.sh из GitHub:
скрипт обновляет /etc/systemd/system/top3-news-daily.timer, вызывает daemon-reload
и перезапускает таймер и бот. Для этих операций необходим интерактивный sudo.
Синхронизация Git checkout сама по себе не активирует новое расписание.
